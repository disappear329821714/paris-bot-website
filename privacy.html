Privacy Policy

This notice explains the information processed by the Paris Discord bot and how its temporary caches differ from persistent records.

1. Operator and contact

The bot is operated by Paris. Contact whereismydiva@gmail.com for support, privacy concerns and data requests. Do not post a deletion request containing private message text in a public support channel.

2. What the bot processes and why

  • Discord information: user IDs, usernames, display names, avatar/banner links, account creation dates, and, where accessible and requested, server membership, join dates and role information. Guild/channel IDs, names, permissions and other Discord metadata support commands, access checks and event handling.
  • Roblox: a requested Roblox username or ID is sent to Roblox to retrieve public profile information and avatar links. Profiles may include a display name, description, creation date and account moderation status.
  • Bloxlink: the current server ID and target Discord or Roblox ID are sent to Bloxlink to resolve existing account links. Linked IDs may be used for further Roblox or Discord lookups. The current integration uses one configured server API key; it does not link accounts or collect users' login credentials.
  • Last.fm: the entered Last.fm username and selected query options are sent to Last.fm. Results include public profile details, listening status, recent tracks and top lists. The bot does not scrobble, sign in to your Last.fm account or automatically associate it with your Discord account.
  • Command controls: requesting Discord user IDs, command names and timing information support cooldowns. Bounded HTTP response bodies are processed to handle API requests.

3. Deleted messages, edits and removed reactions

While running, the bot can receive messages in accessible guild channels before an edit or deletion. Snipe capture is limited to server text and announcement channels where the bot can view and read history. It ignores DMs, threads, bot/webhook-authored messages and unknown authors.

Deleted-message records contain author username/ID, message ID, guild/channel IDs, original and deletion timestamps, up to 3,000 text characters, and up to five attachment names, sizes and eligible Discord CDN links. Edit records contain up to 1,800 characters of before and after text plus author, message and timestamp information. Metadata-only updates and edits without known before-text are skipped. Removed-reaction records contain the emoji, reaction user's name/ID, message author, message ID and removal time; the event does not establish which moderator removed someone else's reaction.

No attachment bytes are downloaded or archived. Deleted attachment links may expire. The bot cannot recover content it never received. Snipe replies are private to the requester, but readers with the required channel access can request them; retrieval is not limited to moderators. Both requester and bot need View Channel and Read Message History. Manage Messages is required to clear a channel's snipe records.

4. Memory caches and retention

Current implementation defaults
InformationLimits and expiry
Snipe history30 minutes after capture, at most 10 combined records per channel and 200 channels. These limits are configurable. Expired records cannot be retrieved; access or a 60-second cleanup sweep removes them. Channel/guild removal and access-loss checks also clear relevant history.
Source Discord messagesDiscord.js caches at most 50 messages per channel, with a 30-minute lifetime and a 60-second sweep. This source cache is separate from snipe records.
Roblox resultsThree caches of up to 500 entries each, with five-minute freshness.
Last.fm resultsRecent/now-playing freshness: 15 seconds, up to 200 entries. Profile/top freshness: five minutes, up to 300 entries. Validated API response bodies can contain more fields than displayed.
CooldownsUp to 5,000 user/command entries with one-hour cache freshness. Individual command cooldowns are shorter.
Other Discord.js metadataUser, member, guild and channel caches have no application-defined time-based retention schedule; updates, removals and process restart affect their lifetime.

Freshness is not immediate deletion: expired Roblox, Last.fm and cooldown entries are no longer returned, but can remain in memory until their next access, replacement, capacity eviction or process restart. All these memory caches, including snipes, disappear when the bot process stops. There is no application database or permanent message archive.

5. Logs and stored configuration

Operational logs include timestamps, startup/connection information, bot/application identifiers, registration guild IDs, command names and error details. A failed member-profile lookup can log the queried Discord user ID. The code does not intentionally log message text or full API responses, and redacts configured API keys and the bot token. This is not a guarantee that every unexpected error contains no personal information.

Local development logs can be stored in files, and production output is handled by PebbleHost. The application currently has no automatic log-retention schedule. Hosting-provider log and backup retention have not been independently verified; no exact deletion period is promised for them. Service credentials and configured IDs persist in private environment/configuration files, outside the public website repository.

6. Who receives information

The bot runs on PebbleHost, which provides its production infrastructure. Discord receives command replies and processes messages under its own terms. Roblox receives requested Roblox identifiers; Bloxlink receives the guild and target account identifiers; Last.fm receives the requested Last.fm username and query options. Those requests use the hosting server's network connection and any required bot service credential. The requester’s Discord ID is not explicitly included in Roblox or Last.fm requests.

Most profile, account-link and Last.fm command responses are public in the invoking channel. Other members may read or copy them. Discord message retention and users' copies are separate from bot memory: clearing a cache does not remove an already posted reply. These external services have their own data practices, and deleting bot records does not delete an account or records held independently by another provider.

7. Requests and choices

Email whereismydiva@gmail.com to request access, correction or deletion of information processed by the bot, or to raise a privacy concern. Include only the Discord user ID and relevant server/channel or command details needed to locate the issue. We may ask for proportionate confirmation that a request concerns your data; never send a password or API key.

A member with Manage Messages can use /clearsnipes to clear current-channel history. There is currently no automated per-user opt-out/deletion command. Administrators can remove the bot or deny channel access. Those actions do not automatically delete public command replies or records held by other services. Depending on applicable law, you may have rights to access, correct, erase, restrict or object to processing, and to complain to a data-protection authority. We review requests and respond as required by applicable law. The bot is hosted in North America and external services may process information in other countries.

8. Security

The bot uses environment variables for service credentials, HTTPS for external API requests, permission checks for snipes, bounded history and response sizes, and rate controls. Secrets and local logs are excluded from Git. Access should be limited to the operator and trusted infrastructure providers. No service can guarantee absolute security; privacy/security incidents should be reported through the private contact.

9. Uploaded-video conversion and inactive features

/ai is not in the active production command set, and the bot does not currently send prompts or images to OpenAI. The MP4 command downloads the video you explicitly attach from Discord to PebbleHost and processes it locally with FFmpeg. Input/output bytes are stored in random temporary working files, not sent to an external conversion provider. Input is limited to 10 MiB and output to at most 8 MiB or the smaller Discord upload allowance. A job has a 90-second active deadline. Working files are deleted after success, failure, upload failure or timeout; startup removes owned crash leftovers older than one hour. Forced termination can delay cleanup until a later startup. Converted responses are uploaded to Discord and visible to people who can access the response; Discord and recipients may retain copies after our working files are deleted. Logs record operation, elapsed time, byte counts and result category, not video contents, original filenames or attachment URLs. The media cooldown keeps a user ID temporarily under the cooldown-cache rules above. External media downloads and automatic link handling are not supported. Public-release preparation includes guild restrictions for snipes and Bloxlink; these local changes must be deployed and this notice checked before public rollout. Material changes to processing will be described here before activation.
